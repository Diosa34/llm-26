# Лабораторная работа №1

## Описание задания

В работе выполняется локальное развёртывание и эмпирический анализ трёх больших языковых моделей (LLM) из разных семейств с использованием **Ollama** и **OpenAI-compatible REST API**.

В эксперименте используются следующие модели:

- **Phi-3.5-mini** — `phi3.5:3.8b-mini-instruct-q4_K_M`;
- **Llama 3.2** — `llama3.2:3b`;
- **Qwen2.5** — `qwen2.5:3b`.

|                 | **Phi-3.5-mini**         | **Llama 3.2 3B**         | **Qwen2.5 3B**               |
| --------------- | ------------------------ | ------------------------ | ---------------------------- |
| Параметров      | ~3.8B                    | ~3.21B                   | ~3.09B                       |
| Слоёв           | 32                       | 28                       | 36                           |
| Hidden size     | 3072                     | 3072                     | 2048                         |
| Attention heads | 32                       | 24                       | 16                           |
| KV heads        | **32**                   | **8**                    | **2**                        |
| Attention       | MHA                      | GQA                      | GQA                          |
| FFN size        | 8192                     | 8192                     | 11008                        |
| Нормализация    | RMSNorm                  | RMSNorm                  | RMSNorm                      |
| Позиции         | RoPE + LongRoPE scaling  | RoPE, Llama 3 scaling    | RoPE, `theta=1e6`            |
| Контекст модели | 128K                     | 128K                     | 32K в исходном 3B checkpoint |
| Vocabulary      | ~32K                     | ~128K                    | ~152K                        |

Phi-3.5-mini — относительно широкая 32-слойная модель с MHA, маленьким vocabulary и очень длинным контекстом.

Llama 3.2 3B — широкая 28-слойная модель с GQA 24 - 8, большим tokenizer и 128K context.

Qwen2.5 3B — более глубокая и узкая 36-слойная модель с очень компактным GQA 16 - 2, огромным vocabulary и RoPE с theta=1e6.

Все три модели запускаются локально на одном и том же компьютере и сравниваются на трёх разнотипных русскоязычных задачах: генерация, классификация и извлечение.

Для каждого сочетания «модель × промпт» выполняются два режима:

- **A — базовый:** параметры генерации не передаются и используются значения по умолчанию движка;
- **B — тюнинг:** изменяются как минимум два гиперпараметра. В эксперименте используются `temperature=0.3` и `max_tokens=150`.

Таким образом, эксперимент содержит **3 × 3 × 2 = 18 запусков**.

## Результаты работы

### 1. Тестовые промпты

Описаны в source/prompts.py

### 2. Что сохраняется для каждого запуска

Для каждой комбинации должны быть сохранены как минимум:

- название и идентификатор модели;
- идентификатор промпта (`P1`, `P2`, `P3`);
- режим (`A_baseline` или `B_tuned`);
- использованные значения гиперпараметров;
- полный текст ответа;
- число токенов входа;
- число токенов выхода;
- общее число токенов;
- полное время отклика;
- скорость ответа в токенах/с;


### 3. Критерии оценки качества

#### P1 — генерация

Качество проверяется в соответствие с требованиями, описанными в промпте.
Адекватность оценивается в соответствие с применимостью ответа в реальной жизни.

#### P2 — классификация

Проверяется полное совпадение с ожидаемой меткой `Расписание`.

#### P3 — извлечение и переформулирование

Проверяется корректность каждого из четырёх полей JSON и соответствие требованиям описанным в промпте. Для каждого ответа можно посчитать число правильно извлечённых полей из 4.

### 4. Стабильность и повторяемость

Для анализа детерминизма дополнительно можно повторить некоторые одинаковые конфигурации несколько раз, например:

- Phi-3.5-mini + P1 + A;
- Phi-3.5-mini + P1 + B;
- Llama 3.2 3B + P2 + A;
- Llama 3.2 3B + P2 + B;
- Qwen2.5 3B + P3 + A;
- Qwen2.5 3B + P3 + B.

Сравниваются идентичность ответа, изменение длины, метрики качества и скорости.

## Выводы

Режим B с temperature=0.3 и max_tokens=150 заметно сокращает latency и повышает практическую скорость генерации у всех трёх моделей, при этом влияние на качество зависит от типа задачи. Для P2 качество не изменилось, для P1 у Phi и Qwen улучшилось, а для P3 в среднем немного ухудшилось.

**Phi-3.5-mini** продемонстрировала заметное улучшение качества на генеративной задаче и при этом существенно ускорилась в режиме B, однако по скорости оставалась ниже двух других моделей. 

**Llama 3.2 3B** показала высокую скорость в обоих режимах, но на задачах генерации и извлечения сохранялись ошибки содержания и структуры.  

**Qwen2.5 3B** показала высокую практическую скорость и хорошие результаты на всех трёх типах задач; на P1 в режиме B качество повысилось до 3/3. На P3, однако, в режиме B произошла потеря одного корректно извлечённого поля  

## Инструкция по запуску

### 1. Установить Ollama

Установить Ollama для Windows с официального сайта:

https://ollama.com/download/windows

После установки проверить:

```powershell
ollama --version
```

### 2. Загрузить модели

```powershell
ollama pull phi3.5:3.8b-mini-instruct-q4_K_M
ollama pull llama3.2:3b
ollama pull qwen2.5:3b
```

Проверить:

```powershell
ollama list
```

Для используемых тегов Ollama публикует модели в своей библиотеке: `phi3.5:3.8b-mini-instruct-q4_K_M`, `llama3.2:3b`, `qwen2.5:3b`.

### 3. Проверить OpenAI-compatible API

Убедиться, что Ollama запущен, затем выполнить:

```powershell
curl.exe http://localhost:11434/v1/models
```

Для проверки chat endpoint:

```powershell
curl.exe http://localhost:11434/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d "{\"model\":\"qwen2.5:3b\",\"messages\":[{\"role\":\"user\",\"content\":\"Ответь одним предложением: что такое LLM?\"}]}"
```

### 4. Создать виртуальное окружение Python

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### 5. Установить зависимости

```powershell
pip install -r requirements.txt
```

### 6. Запустить эксперимент

Предполагается следующая структура проекта:

```text
source/
├── prompts.py
├── experiment.py
└── results/
    ├── raw_results.json
    └── results.csv
```

Основной запуск:

```powershell
python experiment.py
```

После выполнения должны появиться:

```text
results/raw_results.json
results/results.csv
```
